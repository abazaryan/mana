# Решения по «Слуху»

Принято владельцем продукта (Pooya) 11.10.2026. Этот файл — источник правды для SPEC.md и CLAUDE.md. Новые решения добавлять сюда с датой.

## Р1. Отдельный продукт, перенос модулей из LivreVivant

- «Слух» — отдельный продукт, не связан с LivreVivant и его учебником. Пользователь занимается в «Слухе».
- Из LivreVivant переносятся только проверенные модули чистой логики вместе с тестами (каскад проверки набранного ответа, нормализация, раскрытие печатных конвенций, настройка ts-fsrs и формат журнала повторений, часы латентности) и решения о составе сессии — как правила.
- Отчёт о переносе готовится в сессии Claude Code проекта LivreVivant и кладётся в `reference/livrevivant-report.md` (описывает закрытый код, не публикуется). Перенос — до начала этапа «Цикл обучения».
- Код LivreVivant закрытый: копии кладутся во временную папку `reference/` (в `.gitignore`), в репозиторий попадает только перенесённый и адаптированный код.

## Р2. Свой формат колоды вместо APKG

- Колода — ZIP с `deck.json` и папкой `audio/`. APKG в приложении не поддерживается.
- Устойчивые `id` у колоды и записей: повторный импорт исправленной колоды обновляет содержимое и не стирает прогресс.
- Значение записи — на нескольких языках (`tg`, `ru`, `en`, любые из них). Какой показывать, выбирает пользователь в настройках.
- Поля записи: французский текст, IPA, значения, аудио, род (если есть), типы карточек.
- Версия формата в файле (`"format": "sluh-deck", "version": 1`), валидатор с понятными сообщениями об ошибках.
- Урок `apkg/fr_lesson_01.apkg` один раз конвертируется отдельным скриптом (не частью приложения).
- `docs/DECK_PROMPT.md` — инструкция для ИИ, который генерирует колоды.
- Одна запись = одна учебная единица (Unit); каждый тип карточки = отдельный навык (Unit × Skill).

## Р3. Знакомство и навыки

- **Знакомство** (один раз на запись, без оценки в FSRS): французский текст, IPA, значение, род (если есть), аудио → повторить вслух → один раз написать по образцу.
- **Повторения** — три навыка, у каждого своё состояние FSRS:
  - `listen` — услышать и повторить вслух (произношение);
  - `speak` — увидеть значение и сказать по-французски (устное вспоминание);
  - `write` — увидеть значение и написать (орфография).
- `listen` почти не проверяет память (эхо) и не влияет на интервалы `speak`.
- Один правильный ответ на карточку; другая формулировка — отдельная запись.

## Р4. Оценка

- Правило из LivreVivant: правильность определяет оценку. Неверно → «Снова»; частично (почти) → «Трудно»; верно → «Хорошо»; «Легко» — только за устойчиво быстрые верные ответы (точное определение «устойчиво» — из отчёта о переносе).
- Латентность (время до начала ответа) пишется в журнал всегда. По журналу проверяем, не занижает ли правило интервалы.
- Автоматическая оценка показывается вместе с четырьмя кнопками; «Дальше» принимает её одним касанием.
- Правка пользователем:
  - понижать — свободно;
  - повысить с «Снова» — только кнопкой «Меня неправильно распознали»: ответ засчитывается как «Хорошо», в журнал пишется ошибка распознавания;
  - другие повышения разрешены и записываются в журнал. Частые повышения — сигнал менять пороги.
- В FSRS идёт окончательная оценка; в журнале — и предложенная, и окончательная, и причина.

## Р5. Сверка ответа

- Голосовой ответ сверяется по звучанию, а не по написанию: омофоны засчитываются (`parle`/`parlent`, `-é`/`-er`/`-ez`, `ces`/`ses`). Цифры приравниваются к словам («1» = «un»).
- Орфография проверяется только в навыке `write`, каскадом из LivreVivant.

## Р6. Своя клавиатура (только телефон)

- Gboard не отключает подсказки атрибутами поля (проверено пользователем).
- Своя экранная клавиатура на телефоне: QWERTY и отдельный ряд французских букв (é è ê ë à â ç î ï ô û ù ü œ æ, апостроф, дефис). Системная клавиатура скрывается (`inputmode="none"`; надёжность проверить на устройстве).
- На ноутбуке — физическая клавиатура.

## Р7. Состав сессии

- Число повторений определяет FSRS. Пользователь регулирует только новые записи.
- По умолчанию 5 новых записей в день (вариант — 10). Пользователь может увеличить.
- Приложение отслеживает удержание и просроченные повторения при увеличенном объёме и предлагает подходящий. При увеличении показывает, сколько будущих повторений это добавит.

## Р8. Языки интерфейса

- Таджикский, русский, английский. Переводы закладываются с первого экрана цикла обучения.
- Таджикские тексты переводит Claude, пользователь проверяет.
- Язык интерфейса и язык значений в колоде настраиваются отдельно.

## Р9. Пользователи и колоды

- Семья и несколько друзей. У каждого свой аккаунт, регистрация только по приглашению.
- Колоды загружает администратор (Pooya) в общую библиотеку; пользователи выбирают колоды из неё. Прогресс у каждого свой.
- Минимум по GDPR: уведомление о том, что голос уходит в службу распознавания браузера (Google в Chrome, Microsoft в Edge) и где хранятся данные; удаление аккаунта по запросу. Если аккаунт будет у несовершеннолетнего — согласие родителя (возраст проверить для Люксембурга).

## Р10. Синхронизация

- Телефон и ноутбук синхронизируются.
- Данные хранятся локально (IndexedDB), сервер — для синхронизации.
- Журнал повторений только дополняется (записи с UUID); состояние FSRS выводимо из журнала. Синхронизация = объединение журналов.
- Модель данных готова к синхронизации с этапа «Цикл обучения»: UUID, `userId`, журнал только на дополнение.

## Р11. Бэкенд

- Основной план: Cloudflare Workers + D1 + R2 (бесплатный тариф; Workers Paid $5/мес, если перерастём лимиты).
- Вход по приглашению пишем сами (готовых аккаунтов у Cloudflare нет). Библиотеку выбрать на этапе бэкенда.
- Перед этапом бэкенда перепроверить цены, лимиты и возможность хранить данные в ЕС.
- Запасной вариант: Supabase Pro ($25/мес).
- Отвергнуто: бесплатные Supabase и Appwrite (приостановка за неактивность), Firebase (нет потолка расходов), свой сервер (постоянное обслуживание).
