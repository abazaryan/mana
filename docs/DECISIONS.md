# Решения по «Мане»

Принято владельцем продукта (Pooya) 11.10.2026. Этот файл — источник правды для SPEC.md и CLAUDE.md. Новые решения добавлять сюда с датой.

## Р1. Отдельный продукт, перенос модулей из LivreVivant

- «Мана» — отдельный продукт, не связан с LivreVivant и его учебником. Пользователь занимается в «Мане».
- Из LivreVivant переносятся только проверенные модули чистой логики вместе с тестами (каскад проверки набранного ответа, нормализация, раскрытие печатных конвенций, настройка ts-fsrs и формат журнала повторений, часы латентности) и решения о составе сессии — как правила.
- Отчёт о переносе готовится в сессии Claude Code проекта LivreVivant и кладётся в `reference/livrevivant-report.md` (описывает закрытый код, не публикуется). Перенос — до начала этапа «Цикл обучения».
- Код LivreVivant закрытый: копии кладутся во временную папку `reference/` (в `.gitignore`), в репозиторий попадает только перенесённый и адаптированный код.

## Р2. Свой формат колоды вместо APKG

- Колода — ZIP с `deck.json` и папкой `audio/`. APKG в приложении не поддерживается.
- Устойчивые `id` у колоды и записей: повторный импорт исправленной колоды обновляет содержимое и не стирает прогресс.
- Значение записи — на нескольких языках (`tg`, `ru`, `en`, любые из них). Какой показывать, выбирает пользователь в настройках.
- Поля записи: французский текст, IPA, значения, аудио, род (если есть), типы карточек. *(Уточнено 11.10.2026: изучаемый язык задаётся колодой и поле называется `text` — Р13; `determiner` — Р14, перенесён в `form` — Р16; остальные поля — Р15.)*
- Версия формата в файле (`"format": "mana-deck", "version": 1`), валидатор с понятными сообщениями об ошибках.
- Урок `apkg/fr_lesson_01.apkg` один раз конвертируется отдельным скриптом (не частью приложения).
- `docs/DECK_PROMPT.md` — инструкция для ИИ, который генерирует колоды.
- Одна запись = одна учебная единица (Unit); каждый тип карточки = отдельный навык (Unit × Skill).

## Р3. Знакомство и навыки

- **Знакомство** (один раз на запись, без оценки в FSRS): французский текст, IPA, значение, род (если есть), аудио → повторить вслух → один раз написать по образцу. *(Подпись шага вслух — «Бо садои баланд хонед», Р26 п. 1; род слова не повторяется при том же роде формы — Р16, 18.10.2026.)*
- **Повторения** — три навыка, у каждого своё состояние FSRS:
  - `listen` — услышать и повторить вслух (произношение);
  - `speak` — увидеть значение и сказать по-французски (устное вспоминание);
  - `write` — увидеть значение и написать (орфография).
- `listen` почти не проверяет память (эхо) и не влияет на интервалы `speak`.
- Один правильный ответ на карточку; другая формулировка — отдельная запись. Другая форма (род, число, артикль) — тоже отдельная запись с подсказкой формы (Р16).

## Р4. Оценка

- Правило из LivreVivant: правильность определяет оценку. Неверно → «Снова»; частично (почти) → «Трудно»; верно → «Хорошо»; «Легко» — только за устойчиво быстрые верные ответы (определение — следующий пункт).
- «Легко» — верный и быстрый ответ при условии, что предыдущий ответ по той же паре (запись × навык) тоже был верным и быстрым. Быстрый = не дольше 2,5 с + 0,3 с на каждое слово сверх четырёх. Пороги начальные, калибруются по журналу. *(Принято 11.10.2026: в LivreVivant «Легко» не выставляется нигде и определения нет — отчёт о переносе, раздел 5.)* *(Исключение: в `listen` автоматически не ставится — Р25 п. 3.)*
- «Верный» для предыдущего ответа определяется по **окончательной** оценке в журнале, после правки пользователя: например, ответ, засчитанный кнопкой «Меня неправильно распознали», считается верным. *(Принято 11.10.2026.)*
- Латентность (время до начала ответа) пишется в журнал всегда. По журналу проверяем, не занижает ли правило интервалы.
- Автоматическая оценка показывается вместе с четырьмя кнопками; «Дальше» принимает её одним касанием.
- Правка пользователем:
  - понижать — свободно;
  - повысить с «Снова» — только кнопкой «Меня неправильно распознали»: ответ засчитывается как «Хорошо», в журнал пишется ошибка распознавания;
  - другие повышения разрешены и записываются в журнал. Частые повышения — сигнал менять пороги.
- В FSRS идёт окончательная оценка; в журнале — и предложенная, и окончательная, и причина.

## Р5. Сверка ответа

- Голосовой ответ сверяется по звучанию, а не по написанию: омофоны засчитываются (`parle`/`parlent`, `-é`/`-er`/`-ez`, `ces`/`ses`). Цифры приравниваются к словам («1» = «un»).
- Орфография проверяется только в навыке `write`, каскадом из LivreVivant. *(Уточнено: артикль — Р24; пунктуация не учитывается — Р26 п. 5.)*

## Р6. Своя клавиатура (только телефон)

- Gboard не отключает подсказки атрибутами поля (проверено пользователем).
- Своя экранная клавиатура на телефоне: QWERTY и отдельный ряд французских букв (é è ê ë à â ç î ï ô û ù ü œ æ, апостроф, дефис). Системная клавиатура скрывается (`inputmode="none"`; надёжность проверить на устройстве).
- На ноутбуке — физическая клавиатура.
- *(Уточнено Р31, 20.10.2026: буквы изучаемого языка — долгим нажатием вместо отдельного ряда; скрытие системной клавиатуры проверено лабораторией.)*

## Р7. Состав сессии

- Число повторений определяет FSRS. Пользователь регулирует только новые записи.
- По умолчанию 5 новых записей в день (вариант — 10). Пользователь может увеличить.
- Приложение отслеживает удержание и просроченные повторения при увеличенном объёме и предлагает подходящий. При увеличении показывает, сколько будущих повторений это добавит.

## Р8. Языки интерфейса

- Таджикский, русский, английский. Переводы закладываются с первого экрана цикла обучения.
- Таджикские тексты переводит Claude, пользователь проверяет.
- Язык интерфейса и язык значений в колоде настраиваются отдельно.

Если аккаунт будет у несовершеннолетнего — согласие родителя (возраст проверить для Люксембурга). *(Уточнено Р33 пп. 12, 13, 16: одно правило для всех — до 16 лет согласие родителя; Люксембург — 16; уведомление и удаление — по Р33.)*

## Р15. Доработка формата колоды

Принято 11.10.2026.

- Род: `m` / `f` / `n`. Какие роды есть в языке, знает языковой пакет (во французском `n` — ошибка).
- `hint` — подсказка до ответа, `note` — заметка после ответа; обе на нескольких языках интерфейса, как `meaning`.
- Теги: в колоде словарь `tags` — код тега → название на нескольких языках интерфейса (`{"word": {"tg": "вожа", "ru": "слово", "en": "word"}}`); записи ссылаются на коды. Приложение показывает название на языке интерфейса, а если его нет — любое имеющееся. Рекомендуемые коды: `word`, `phrase`, `number`. Валидатор предупреждает о тегах без описания. *(Уточнено 11.10.2026.)*
- Порядок записей в колоде — порядок знакомства с новыми записями.
- Название колоды — имя импортируемого ZIP-файла без расширения, на любом языке; в `deck.json` названия нет. Прогресс привязан к `id` колоды; при повторном импорте новой редакции название обновляется по имени нового файла. *(Уточнено 11.10.2026; многоязычные `title`/`description` отменены.)* *(Заменено Р30, 20.10.2026: название — поле `title` в `deck.json`; имя файла — только при установке колоды без `title`.)*
- `revision` — номер редакции колоды, растёт при каждом изменении. При импорте: записи, которых нет в новой редакции, скрываются, их прогресс не удаляется; при загрузке редакции старее установленной приложение предупреждает.
- Аудио — только WAV или MP3. Если архив больше 20 МБ, валидатор предупреждает (порог подтверждён 11.10.2026). *(Уточнено Р33 п. 14, 21.10.2026: звук необязателен, по каждой записи; без файла — голос браузера.)*
- Версия формата остаётся `1`: колод в старом виде никто, кроме конвертера урока 1, не делал.

## Р16. Форма ответа (`form`) вместо печатных конвенций

Принято 11.10.2026.

- Печатные конвенции (`ravi(e)`, `A / B`, `le/la …`) в колоде не используются: вместо нескольких правильных ответов — отдельные записи с подсказкой формы. `ravi(e)` → записи «ravi» и «ravie».
- Поле записи `form: { determiner, gender, number }` — подсказки **до ответа** на языке интерфейса. `determiner` (`definite` | `indefinite`) перенесён сюда из Р14 с теми же подписями; `gender` — род нужного ответа (`m` | `f` | `n`, только роды языка колоды); `number` — `singular` | `plural`.
- Поле записи `gender` остаётся родом самого слова и показывается **только при знакомстве**, не при вспоминании.
- Подписи формы: tg — род «музак.» (музаккар) / «муан.» (муаннас) / «хунсо», число «танҳ.» / «ҷамъ», определённость «муай.» / «номуай.»; ru — «м. р.» / «ж. р.» / «ср. р.», «ед. ч.» / «мн. ч.»; en — «m.» / «f.» / «n.», «sg.» / «pl.». *(tg подтверждено пользователем 11.10.2026.)*
- **Навыки у форм.** Формы, которые звучат одинаково (`ravi` / `ravie`, `ami` / `amie`), — навык `speak` только у одной записи, `write` у обеих. Формы, которые звучат по-разному (`petit` / `petite`, `voisin` / `voisine`), — `speak` у обеих. Решает автор колоды (правило — в `DECK_PROMPT.md`). *(Принято 11.10.2026.)*
- Валидатор предупреждает, если в `text` остались «(» или «/». Старое поле `determiner` вне `form` — ошибка с подсказкой, как перенести.
- *(Уточнено 18.10.2026: при знакомстве род слова (`gender`) показывается, только если в `form` нет рода или он другой — «un ami»: «номуай. · музак.», а не «музак. · номуай. · музак.»; функция `introHints`.)*
- *(Уточнено Р28, 18.10.2026: `form.gender` обязателен у слов с изменяемым родом, даже если в колоде одна форма; у подлежащего il/elle/ils/elles и числа un/une.)*
- Версия формата остаётся `1`: колод в старом виде, кроме урока 1, нет; урок 1 пересобран конвертером.

## Р17. Правила состава сессии (из LivreVivant)

Принято 11.10.2026. Уточняет Р7; источник — отчёт о переносе, раздел 7.

1. **Сессия — порция**, например 15 карточек; после неё приложение предлагает «ещё порцию». Порция не ограничивает число повторений за день — его определяет FSRS (Р7).
2. **Порядок:** сначала просроченные повторения, самые старые первыми. Затем новые записи: знакомство (Р3) в начале сессии, первые карточки её навыков (`speak`, `write` если есть, `listen`) — в конце той же сессии.
3. **Новое вспоминается в тот же день**, в конце сессии, а не на следующий день: карточки между знакомством и вспоминанием гасят эхо памяти. Наблюдаем по журналу: если ответы в тот же день заметно точнее, чем назавтра, эхо не погашено.
4. **Мягкий запрет новых при долгах.** Если есть повторения, просроченные с прошлых суток, новые по умолчанию не выдаются; приложение показывает причину и кнопку «всё равно добавить». *(Уточнено Р29 п. 5: долги по всем колодам, кнопка — на одну порцию.)*
5. **Лимит новых** — из настройки Р7 (по умолчанию 5 в день). Считается по журналу за сегодня, а не по сессии: перезагрузка не даёт новую пачку. Порядок проверок: есть ли материал → лимит → долги.
6. **Не показывать «гору».** В сессии — «X из N»; общий остаток показывается не больше «25+». Точное число приложение считает для слежения за удержанием и прогноза (Р7). *(Уточнено Р29 п. 6.)*
7. **Новое не прячется без объяснения.** Если новых нет, показывается причина: нет материала / лимит на сегодня / долги / места заняли повторения — на языке интерфейса (Р8).
8. **Одно определение «карточки, которую можно выдать»** — общее для состава сессии и для счётчиков лимита.
9. **Скрытые записи** (пропавшие из новой редакции колоды, Р15) не выдаются; уже состоявшиеся сегодня знакомства с ними засчитываются в лимит.
10. **Сутки — местные сутки устройства, граница в 04:00**: занятие после полуночи идёт в счёт того же дня. *(Уточнено Р29 п. 3: пояс устройства на момент ответа, день срока.)*
11. **«Не знаю»** = «Снова». После «Снова» — короткое повторение, своё для навыка: `speak` — прослушать и сказать; `write` — напечатать один раз; `listen` — повторить вслух. Четыре кнопки оценки и правка — по Р4.
12. **Аудио до ответа** — только в `listen`, где оно и есть вопрос. В `speak` и `write` аудио до ответа не звучит.
13. **Правильный ответ не держится в странице** до ответа.
14. Правило LivreVivant «новые только из открытых глав» **отклонено**: глав нет; порядок задают записи колоды (Р15) и выбранные колоды (Р9).

## Р18. Модель данных и импорт (этап 4.1)

Принято 11.10.2026. Схема — `docs/DATA_MODEL.md`.

## Р22. Этап 4.2: знакомство, навык `speak`, сверка по звучанию, раскраска ответов

Принято 13.10.2026, план этапа подтверждён с правками 14.10.2026. Объём этапа 4.2: знакомство, `speak`, сверка по звучанию (Р5), оценка и её правка (Р4), FSRS, журнал, раскраска ответов. `listen`, `write`, повторение после «Снова», мягкий запрет новых, «25+» и рекомендация объёма — этапы 4.3–4.4.

1. **Сверка по звучанию** — в языковом пакете: нормализация, цифры → слова, **явные** правила омофонов (для французского: `-é`/`-er`/`-ez`, `-e`/`-es`/`-ent` у глаголов, `ces`/`ses`, `c'est`/`s'est` и т. п.), выбор лучшей из альтернатив распознавателя. Принцип: **ложное «верно» хуже ложного «Снова»** (от ложного «Снова» есть кнопка «Меня неправильно распознали»). Общей фонетики нет: всё, чего нет в списке правил, — другое слово. Исключения правил (например, слова, где `-er` читается [ɛʁ]: cher, hier, fier, hiver, super…) — закрытым списком в данных языкового пакета, не в коде правила; тест на каждое слово. Цифра «1» = только «un» (не «une»); распознанный текст пишется в журнал всегда. *(Уточнено 14.10.2026.)*
2. **Вердикт голоса** *(уточнено 14.10.2026, заменяет правило «4+ слов, одна ошибка»)*. N — число слов эталона (как написано; элизия вместе со следующим словом: `je m'appelle Anna` = 3 слова). E — слова эталона, которые не прозвучали (не сказано или распознано другое слово); лишние слова в E не входят; `euh`/`heu`/`hum` не учитываются.
   - E = 0 и лишних нет → верно;
   - E = 0, лишних сколько угодно → почти;
   - единственное непрозвучавшее — артикль (в том числе элидированный `l'`), **отсутствующий** в ответе (не заменённый другим словом), при этом остальная часть эталона сказана → почти *(уточнено 16.10.2026, см. п. 7)*;
   - E ≤ ⌊0,25 × N⌋ → почти; иначе → неверно;
   - другой или лишний артикль при подсказке формы `determiner` → неверно.
   Порог 0,25 — именованная константа; в журнал пишутся N, E и число лишних слов.
3. **Латентность голоса** — от max(показ карточки, микрофон готов) до начала речи. Задержка включения микрофона и коды ошибок распознавателя пишутся в журнал отдельно.
4. **Состав сессии** — чистая функция `buildSession` в `src/core`: сначала просроченные `speak` (самые старые первыми), затем новые записи по порядку колоды. Лимит новых — из настроек (5), по журналу за местные сутки с границей 04:00. Порция — 15 (просроченные + вспоминания новых; знакомства не считаются). **Порядок показа: знакомства → просроченные → вспоминания новых** — это уточняет Р17 п. 2: повторения стоят между знакомством и вспоминанием и гасят эхо. *(Уточнено 14.10.2026.)*
5. **Знакомство**: текст, IPA, значение, род, форма, аудио → повторить вслух (распознаётся, без оценки, можно пропустить) → написать по образцу (только у записей с навыком `write`; проверка каскадом `evaluate.ts`, без оценки) → запись знакомства в журнал.
6. **Экран `speak`**: до ответа — значение, подсказка формы, `hint`. Ответ голосом, текстом (та же сверка по звучанию) или «Не знаю» (= «Снова»). После ответа — текст, IPA, `note`, автоматически звучит аудио колоды; предложенная оценка, четыре кнопки и «Дальше»; правка по Р4, включая «Меня неправильно распознали». «Снова» при ответе текстом повысить нельзя (распознавания не было). *(Уточнено 14.10.2026.)*
7. **Журнал ответа**: предложенная и окончательная оценка, причина, способ ввода, распознанный текст и альтернативы, уверенность распознавателя, латентность, задержка микрофона, ошибки распознавателя, N, E, число лишних слов.
8. **Новые строки** tg/ru/en; таджикские — по `docs/GLOSSARY_TG.md`, для слов не из глоссария — кандидаты (Иран → Афганистан → Таджикистан). Без длительного вида с «истодан»; кнопки — краткой формой без «кардан». Новые термины — в глоссарии, раздел «Занятия» (утверждены 14.10.2026).
9. **Раскраска ответов** — только поведение по образцу Anki («type in the answer») и Duolingo, без кода Anki (AGPL):
   - а) набранный ответ — посимвольно. Статусы: верно / замена / пропущено / лишнее / только диакритика (диакритика — отдельный цвет, это «почти»). Раскраску строит та же функция `src/core`, что выносит вердикт, с той же нормализацией: цвета не могут противоречить оценке; *(Знаки препинания — нейтральный статус, на вердикт не влияют — Р26 п. 5.)*
   - б) голосовой и текстовый ответ в `speak` — по словам, по звучанию, после ответа. Статусы: верно / засчитано по звучанию / распознано другое слово / не сказано / лишнее. Та же функция выравнивания выносит вердикт (п. 2);
   - в) «повторить вслух» в знакомстве (текст виден): слова подсвечиваются по мере распознавания (промежуточные результаты), итог — по окончательному результату;
   - г) **вид — блоки по словам** *(уточнено 14.10.2026)*: в каждом блоке сверху ответ (услышанное), снизу эталон; блок переносится целиком, верх и низ всегда друг над другом (не две независимые строки, выровненные по символам). Границы блоков — где пробел есть хотя бы в одной из строк. Пропущено: в ответе пустая ячейка (пунктирная рамка), в эталоне символ или слово со статусом «пропущено». Лишнее: в ответе зачёркнуто, в эталоне пустая ячейка. Замена: в ответе красным, в эталоне правильный символ напротив. Пропуски и лишнее — для любых символов и слов, не только артикля;
   - д) не только цвет: второй признак (зачёркивание, пунктир, значок); проверить светлую и тёмную тему;
   - е) подписи не обещают оценку произношения: «распознано другое слово», а не «неправильно произнесено».

### Р22, уточнения после проверки на телефоне (15.10.2026)

Журнал проверки: 72 записи; микрофон включается за 60–130 мс, начало речи всегда по `speechstart`, распознаватель на Android даёт одну альтернативу, ложных «верно» нет. Короткие числа («un», «deux», «trois») распознаватель возвращал пустыми.

1. **Правило З9**: -e после произносимой конечной согласной не меняет звучание (tadjik = tadjike, seul = seule, noir = noire, normal = normale, espagnol = espagnole, dur = dure, meilleur = meilleure). Окончания основы и исключения — закрытыми списками в данных французского пакета; не применяется к -er, к gentil / gentille, к словам с немой или меняющейся согласной (petit ≠ petite, grand ≠ grande, actif ≠ active) и к носовым (un ≠ une, fin ≠ fine, brun ≠ brune).
2. **«Легко» не предлагается**, если в этой карточке до успеха были нераспознанные попытки или «Повторить» (предлагается «Хорошо», причина «верно, но не с первой попытки»).
3. **Три нераспознанные попытки подряд** — блок микрофона заменяется крупным подсвеченным полем ввода с курсором, без текстовой подсказки.
4. **Подсказки распознавателю (эксперимент)**: `SpeechRecognition.phrases`, при наличии языкового пакета на устройстве — `processLocally`. Словарь — слова всех записей установленных колод того же языка, не ожидаемый ответ. Переключатель в Настройках, по умолчанию выключен. После первой ошибки `phrases-not-supported` устройство запоминает «не поддерживается» и больше не отправляет подсказки, пока переключатель не выключат и не включат снова; попытка сразу повторяется без подсказок. Кнопка скачивания языкового пакета — только по нажатию пользователя. В журнал: `biasing`, `processLocally`, число подсказок, состояние пакета, код `phrases-not-supported`.
5. Из исключений З1 убраны ranger, mixer, poster, boxer (частые глаголы на [e]); fier остаётся.
6. **Знакомство — по шагам**: карточка → «повторите вслух» → «напишите по образцу»; пройденный шаг уходит с экрана.
7. **Всё совпало** (в том числе по звучанию) — одна строка с ✓; у совпавших по звучанию слов приглушённый ≈. Две строки — только при расхождении.
8. Без подписей строк и легенды. В начале строки ответа — 🎤 (голос) или ⌨ (набор); эталон — тем же шрифтом, что главное слово карточки. Пояснение статуса («услышано: X», название статуса) — по нажатию на блок.
9. Совпадение по цифрам показывается как обычное «верно», без ≈ (в журнале правило «Ч» остаётся).
10. Исправленные символы и слова в эталоне — жирные и зелёные.
11. Элизия показывается слитно (c'est — один блок).
12. Распознаватель — за интерфейсом `SpeechRecognizer` (`src/core/ports.ts`); ядро не зависит от Web Speech. Облачный сервис (Whisper или Deepgram через Cloudflare, Google) — отдельный адаптер в `src/platform`.

### Р22, уточнение 16.10.2026 (правило артикля; найдено при подготовке эксперимента по распознавателю)

7. Исключение «единственное непрозвучавшее — артикль → почти» действует, только если артикль (включая элидированный `l'`) в ответе **отсутствует**, а остальная часть эталона сказана. ## Р23. Распознаватель речи: остаёмся на Chrome Web Speech

Принято 16.10.2026 по результатам эксперимента (`docs/RECOGNITION_EXPERIMENT.md`, коммиты c274e3c, 59f8204).

1. **Решение.** Голос распознаёт Chrome Web Speech (адаптер `src/platform/speech.ts`, порт `SpeechRecognizer` остаётся). Облачный адаптер, прокси Cloudflare и ключи для распознавания не делаются.
2. **Основание.** Ошибки Chrome безопасны, ошибки облака опасны.
   - Chrome: пустой ответ → просьба повторить, после трёх → ввод текстом. Это стоит времени, а не неверных оценок. С повторами Chrome засчитал неверных 1 из 31 и отверг верных 0 из 43; с первой попытки — пустой ответ в 20 из 74 пунктов, в том числе на 9–10 из 14 коротких слов.
   - Облако на похожих словах (другое слово, близкое к эталону) отвечает словом эталона → ложное «верно»: Deepgram 3 из 10, Whisper 1–2 из 10, Chrome 0 из 10. Принцип Р22.1: ложное «верно» хуже ложного «Снова».
3. **Запасной вариант:** гибрид «Chrome → Whisper large-v3-turbo с фильтром тишины (`vad_filter`) при пустом ответе Chrome» (по оценке задним числом: облако нужно на ≈ 27 % попыток, ≈ 14 мин/сутки, в бесплатных пределах Cloudflare; ложных «верно» 4 против 3, коротких отвергнуто 2 против 10). **Условие пересмотра**: за 2–3 недели занятий больше 30 % голосовых карточек требуют ≥ 2 попыток (по журналу: `retries`, `recognitionErrors`), или у нового пользователя Chrome справляется заметно хуже. Записи и кэш ответов сервисов сохраняются в `E:\dev\mana-lab\` (вне репозитория).

## Р29. Этап 4.4а: механика повторений, сутки и пояса, долги, числа в конце порции

Принято 18.10.2026 (план 4.4а с дополнением подтверждён). Этап 4.4 разделён: **4.4а** — механика повторений (этот пункт); **4.4б** — практика без оценки, целевое удержание в Настройках, рекомендация объёма Р7 с двумя счётчиками новых, сверка значений между колодами при импорте (Р28 п. 8) — после пересмотра журнала в начале ноября.

1. **Без шагов в минутах.** ts-fsrs: `learning_steps: []`, `relearning_steps: []`, `enable_short_term: true`, остальное по умолчанию (удержание 0,9, параметры FSRS-6, fuzz выключен). Любой ответ назначает срок в днях. Тот же день закрывают вспоминание новых в конце порции (Р17.3) и возврат после «Снова» (Р25.6). Расчёт (ответ в 10:00): новая «Снова» — 1 день (S 0,21), «Трудно» — 1 день (S 1,29), «Хорошо» — 2 дня (S 2,31), «Легко» — 8 дней (S 8,3).
2. **Возврат после «Снова» не меняет FSRS** (заменяет Р25.6 в части FSRS). Возврат пишется в журнал как ответ с оценкой (`requeue`, `sincePairSec` и прочее — как раньше), но состояние карточки не меняет: срок задаёт первое «Снова». Основание: без шагов это единственный ответ в тот же день, S он почти не меняет, а правило ts-fsrs «Хорошо ≥ Трудно + 1 день» даёт только удлинение срока; перед ним было короткое повторение с правильным ответом (эхо). Расчёт: новая «Снова» + возврат «Хорошо» — 1 день (S 0,21) вместо 2 дней (S 0,25); повторение «Снова» + возврат «Хорошо» — 2 дня (S 1,54) вместо 3 (S 1,57); повторное «Снова» на возврате больше не поднимает D. Второй возврат — по-прежнему только после «Снова» на первом. Пересчёт журнала пропускает возвраты (`requeue > 0`) в записях любой версии. Поиск предыдущего ответа для «Легко» тоже пропускает возвраты (на деле «Легко» после «Снова» по-прежнему невозможно на следующем ответе).
3. **Сутки приложения и пояс.**
   - Сутки — местные сутки устройства с границей в 04:00 (час — именованная константа). Местное время считается по поясу устройства на момент ответа: IANA-имя через Intl и смещение для конкретной даты, не константой.
   - **День срока** = сутки приложения последнего ответа (по поясу этого ответа) + интервал в днях. Карточка доступна, когда этот день наступил по текущему поясу. Правило «срок раньше ближайших 04:00» не используется (давало сдвиг на день в час перевода часов). Данные FSRS не меняются: срок в базе — реальное время.
   - **Переходник для ts-fsrs** — в одном месте планировщика: время ответа и время прошлого ответа сдвигаются на (смещение пояса − 4 ч) своего ответа, поэтому «дни по UTC» внутри ts-fsrs совпадают с сутками приложения. В базе — реальное время.
   - В каждую запись журнала (ответ, знакомство, drill) пишется пояс: `tz` (IANA) и `tzOffsetMin` (минуты к востоку от UTC). Пересчёт FSRS из журнала берёт пояс записи. Старые записи без пояса считаются Europe/Luxembourg.
   - Счётчики «сегодня» (лимит новых, добор, долги, числа в конце порции) — по текущему поясу устройства.
   - Расчёт поездок (план 4.4а): ответы по одной паре в двух поясах сдвигают счёт на ±1 день (Люксембург 23:00 → Душанбе 06:00 — 1 день; Люксембург 10:00 → Нью-Йорк 23:00 — 0 дней); в день перелёта возможен один лишний лимит новых (знакомства в Люксембурге в 20:00, в Душанбе в 07:00 следующего утра — новый день); день лимита не пропадает. Принято как есть.
4. **Версия правил в записи ответа** (`rules: 2`). При пересчёте версия записи определяет правила. Записи без версии пересчитываются по правилам 4.4а с поясом Europe/Luxembourg (вариант Б). Сроки, записанные в старых записях, остаются историей; тест «пересчёт даёт записанный срок» проверяет записи версии 2.
5. **Мягкий запрет новых (Р17.4).** Долг — карточка, которую можно выдать (Р17.8), с днём срока в прошлых сутках, в любой колоде пользователя (как лимит новых). Проверка — при каждой сборке порции: разобрали долги — следующая порция с новыми. Порядок проверок: есть ли материал → лимит → долги → места. При долгах не выдаются знакомства и добор навыков (Р25.9); вспоминания сегодняшних знакомств не закрываются никогда (Р17.3). Причина на экране; если долги в другой колоде — с её названием. Кнопка «всё равно добавить» действует на одну порцию: вспоминания новых (сегодняшние и новые в пределах лимита) занимают места первыми, остальные — долги и сегодняшние повторения, затем добор; порядок показа прежний: знакомства → повторения → первые карточки кругами, с разнесением (Р25.8).
6. **Конец порции и пустая очередь.** «Сегодня ещё N» — по этой колоде (к нему привязана «Ещё порция»); «завтра N» и «за 7 дней N» (с завтра на 7 дней, без сегодня) — по всем колодам пользователя. Число «за 7 дней» учитывает только назначенные сроки и вырастет от будущих ответов. У каждого числа предел «25+»; точные числа — только для расчётов. Одна строка с причиной, почему нет новых (Р17.7); строка «новых записей нет» при сработавшем лимите убрана. Экран колоды: «к повторению сегодня: N» (25+) и строка о долгах. N в «X из N» — без знакомств (на карточке знакомства — «Знакомство»); рост N после «Снова» остаётся.
7. **Разовый пересчёт карточек** из журнала по этим правилам при первом запуске новой версии. Перед ним — экран с одной кнопкой «Сохранить и продолжить»: касание сохраняет журнал в файл, затем пересчёт. До нажатия заниматься нельзя; закрыть без нажатия — ничего не меняется, экран при следующем запуске. Журнал при пересчёте не меняется (пересчитывается только выводимая таблица карточек). До публикации — таблица «срок был → станет» по журналу владельца.
8. **Строки** (tg утверждены владельцем 18.10.2026): `study.nothing` «Ҳоло чизе барои такрор нест.»; `study.noNew.overdue` «Аввал такрорҳои рӯзҳои гузашта, баъд омӯзбаргҳои нав.»; `study.addAnyway` «Ба ҳар ҳол илова» («илова» — утверждённый термин; строки резервной копии не меняются); `study.left.today` «Имрӯз мондааст: {n}»; `study.left.tomorrow` «Фардо: {n}»; `study.left.week` «Дар 7 рӯзи оянда: {n}»; `deck.dueToday` «Имрӯз барои такрор: {n}»; `deck.overdue` «Аз рӯзҳои гузашта: {n} — омӯзбаргҳои нав баъд аз онҳо»; `study.noNew.overdueIn`, `study.noNew.overdueMore`, `deck.overdueIn` — как в дополнении к плану; экран пересчёта — «Қоидаҳои такрор барӯз шуданд», «Захира ва идома», «барои эҳтиёт»; журнал — тем же словом, что в кнопке резервной копии («таърихча»).

### Р29, уточнения 19.10.2026 (после проверки на телефоне)

9. **Разнесение карточек одной записи (Р25.8) в хвосте порции.** Карточки одной записи (или одинаково звучащих записей) с k оставшимися карточками должны начаться не позже места L − 1 − (k − 1)·3 (L — длина порции); записи с совпадающими последними местами — по плановому порядку, каждая на место раньше. При нехватке мест — прежний порядок, без ошибки. Повод: 19.10 oui/write и oui/listen шли подряд после 12 повторений.
10. **Добор — тоже «новое» для пользователя** (в журнале различие остаётся). Экран колоды — одна строка «Имрӯз барои такрор: {n} · нав: {m}» / «К повторению сегодня: {n} · новых: {m}» / «Due today: {n} · new: {m}», m — все новые карточки, которые можно выдать сегодня (вспоминания новых записей и добор, с учётом обоих лимитов; долги число не уменьшают), «· нав: {m}» только при m > 0. Конец порции: «Имрӯз мондааст» — повторения и новые вместе.
11. **Причины.** Одна строка лимита для обоих лимитов: «Саҳмияи имрӯзи омӯзбаргҳои нав тамом шуд.» / «На сегодня новых больше нет: дневной лимит исчерпан.» / «No more new cards today: daily limit reached.» (утверждено 19.10.2026; «саҳмия» — дневной лимит новых, Иран سهمیه). Порядок проверок остаётся по п. 5: материал (новые записи или добор) → лимиты → долги → места; если при долгах ждёт только добор — причина «долги» и кнопка «Ба ҳар ҳол илова» (она даёт и добор). «Новых записей не осталось» — только когда порция пуста.
12. **Термин** «навык» — «маҳорат» (в глоссарии; на экран пока не выводится).

## Р30. Название колоды — из `deck.json`

Принято 20.10.2026. Заменяет Р15 в части названия. Повод: Chrome на Android при повторном скачивании дописывает к имени файла суффикс («test-speak-2», «Фаронсавӣ · Дарси 01-1»), а члены семьи получают колоды скачиванием.

1. **Поле `title`** в `deck.json` — название на языках интерфейса `{ tg, ru, en }` (хотя бы на одном), как названия тегов. Приложение показывает название на языке интерфейса, иначе любое имеющееся.
2. **Есть `title`** — название всегда из колоды, имя файла не важно (и при установке, и при обновлении).
3. **Нет `title`** — при установке название — имя ZIP-файла без расширения (как раньше); при обновлении название не меняется. Суффиксы «-1», «(1)» из имени файла не убираются: их не отличить от настоящего названия.
4. **Проверка колоды** (`deck:check` и импорт): нет `title` — предупреждение (по Р28 колода проходит без предупреждений, так что поле фактически обязательно); неверный тип — ошибка; ключ языка не из `tg` / `ru` / `en` — предупреждение. Поле `description` по-прежнему не используется (предупреждение).
5. **Где название показывается**: список колод, экран колоды, занятие, строки о долгах в другой колоде, экран импорта, предупреждения К1 / К2.
6. **Уже установленные колоды** исправляются новой редакцией с `title`: Урок 1 — редакция 3 (tg «Фаронсавӣ · Дарси 1», ru «Французский · Урок 1», en «French · Lesson 1»), тестовая колода — редакция 9 («test-speak» на трёх языках); содержание не меняется.
7. `DECK_PROMPT.md`: ИИ заполняет `title` на языках значений из задания; имя ZIP-файла по-прежнему предлагает.

## Р31. Своя клавиатура на телефоне (этап 5, уточняет Р6)

Принято 20.10.2026 по итогам временной лаборатории клавиатуры (страница удалена 20.10.2026 после приёмки этапа 5; телефон Android 10, Chrome 155, Gboard; ноутбук Edge 155).

0. **Основание.** При `inputmode="none"` Gboard не появляется — ни при касании, ни после переключения приложений, ни после поворота; каретка ставится касанием, вставка работает. С системной клавиатурой (атрибуты `TypeField`) полоса подсказок остаётся, на французской раскладке — слова словаря: `write` не защищён. Edge соблюдает `autocomplete="off"`. Вариант А (своё поле `<input>` + своя клавиатура) подтверждён, А′ (без `<input>`) не нужен.
1. **Где.** Во всех полях ответа (`TypeField`: `write`, шаг письма в знакомстве и в коротком повторении, ответ текстом в `speak` / `listen`, поле после трёх неудач) на устройстве с `pointer: coarse`; системная клавиатура скрыта (`inputmode="none"`). На ноутбуке — физическая клавиатура, своя не показывается.
2. **Раскладка — данные языкового пакета** (Р13): ряды букв, ⇧ и ⌫ вокруг последнего; нижний ряд — апостроф, дефис, пробел, «.», ⏎. Буквы изучаемого языка — долгим нажатием на базовую букву (французский: e → é è ê ë, a → à â æ, c → ç, i → î ï, o → ô œ, u → û ù ü); знаки препинания — долгим нажатием на «.», набор — тот же список, что не учитывается в `write` (Р26), один в пакете. Клавиши с вариантами помечены точкой. Отдельного ряда букв нет. **Цифр нет**: числа в полях ответа — прописью; если понадобятся — отдельный верхний ряд. Голосовая сверка (цифры = слова, Р5) не меняется. *(Уточнено Р41, 25.10.2026.)*
3. **Размер.** Высота клавиши не меньше, чем в Gboard (по снимкам владельца при ширине телефона 412 CSS px — ≈ 44 px вертикально и ≈ 36–38 px горизонтально, ширина ≈ 35 px); начальное значение — 54 px (`KEY_HEIGHT_PX`), в низком горизонтальном окне — 40 px. Gboard выше (≈ 383–387 px) из-за ряда цифр, панели и полосы автозаполнения.
4. **«Назад»** Android при открытой своей клавиатуре сворачивает её и не уходит со страницы (`CloseWatcher`); история и маршруты на `#/…` не затрагиваются. Касание вне поля тоже сворачивает.
5. **Горизонталь** — компактная своя клавиатура; пока она открыта, шапка и строка прогресса скрыты.
6. **Enter** — по Р26 без изменений: ⏎ своей клавиатуры = «Проверить», затем фокус на «Дальше», клавиатура сворачивается; на следующей карточке с полем открывается сама.
7. **Латентность и журнал.** Латентность (Р21) — от касания первой клавиши своей клавиатуры. Ответ текстом пишет `keyboard` (`onscreen` / `system` / `physical` — по первому набранному символу) и `pasted`. После вставки каретка — в конце вставленного.
8. **Настройка «Системная клавиатура»** — на устройстве (не синхронизируется), по умолчанию выключена: для экранного диктора, голосового набора и на случай сбоя; ответы с ней в журнале — `keyboard: system`.
9. **Экранный диктор.** ⇧, ⌫, пробел, апостроф, дефис — словами; у клавиш с вариантами — «удерживайте: …» с перечнем; ⏎ — «Проверить» / «Дальше». Таджикские термины и описание настройки — `GLOSSARY_TG.md`, раздел «Клавиатура» (утверждены владельцем 20.10.2026).
10. **Лаборатория** клавиатуры удалена 20.10.2026 — после проверки новой клавиатуры на телефоне; этап 5 принят владельцем 20.10.2026.

## Р33. Этап 6: аккаунты, синхронизация, личные колоды

Принято 21.10.2026 (решения владельца 20–21.10.2026; исследование и план — `docs/STAGE6_RESEARCH.md`, принят владельцем с ответами на вопросы 11.4). Уточняет Р9, Р10, Р11, Р15; заменяет Р25 п. 2 (п. 14 ниже).

1. **Части этапа.** **6а** — вход по приглашению, синхронизация журнала и настроек, перенос локальных ответов в аккаунт, удаление аккаунта, уведомление о данных. **6б** — общая библиотека колод администратора и личные колоды пользователей в R2. **Часть П** — личные колоды без сервера (проверка в приложении, импорт `deck.json`, голос браузера, инструкция для ИИ, строка о голосе по Р9) — до 6а и до того, как семья начнёт заниматься.

3. **Ресурсы и тариф.** D1 и R2 создаются с юрисдикцией `eu` (изменить после создания нельзя); команду создания владелец подтверждает дословно до выполнения. Тариф — **Free**; переход на Workers Paid ($5/мес), когда база D1 дойдёт до ≈ 300 МБ (предел Free — 500 МБ на базу). Логи Cloudflare выключены. Отдельный токен сборки «mana build token» — без права на D1; миграции D1 применяются вручную отдельным токеном администратора до публикации кода, который их требует. Токен администратора — в `tools/.env` (вне git), в терминал, логи и отчёты не выводится.
4. **Вход без пароля.** Ссылка-приглашение (случайный токен 256 бит во фрагменте адреса `#/join/…`, 48 часов, одно использование, в базе — только SHA-256) создаёт аккаунт и первое устройство. Новое устройство — код привязки с вошедшего устройства (8 знаков, 10 минут, одно использование, счётчики неудачных попыток) или новая ссылка от администратора. Потеря всех устройств — новая ссылка от администратора. Почтового сервиса нет; ключи доступа (passkeys) — возможно позже. Реализация — **своя на Web Crypto, без библиотеки входа** (по образцу эталонного кода Lucia). Администратор создаёт приглашения и ссылки восстановления скриптами `tools/admin/` через `wrangler`, без админ-интерфейса в 6а; ссылка — в буфер обмена, не в терминал.
5. **Сессия.** Непрозрачный токен, в базе — хэш. Cookie `__Host-mana_s`: `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/`, 400 суток (предел Chrome), обновляется не чаще раза в сутки. На сервере сессия истекает после **180 суток без запросов**. CSRF: `Sec-Fetch-Site` / `Origin`, тело только JSON, без CORS. Отзыв устройства — из Настроек любого своего устройства или скриптом.
6. **Перенос локальных ответов.** При первом входе на устройстве с ответами приложение предлагает перенести ответы этого устройства в аккаунт; перед этим владелец сохраняет журнал в файл. Аккаунт получает `userId` первой установки, которая переносит ответы, — её записи не переписываются. Устройство с ответами под другим `userId` до первой отправки меняет `userId` в своих записях (UUID, время, ответы, `deviceId` — без изменений); прежний `userId` сохраняется у аккаунта как прежний. Перенос идемпотентен. **Критерий приёмки** — даты следующих повторений до и после переноса совпадают. Порядок первого входа: журнал в файл → телефон → ноутбук (в Edge на новом адресе ответов нет — ноутбук получит журнал телефона).
7. **Восстановление из файла со входом** (снимает отказ Р18 п. 3 / `planRestore`): файл с `userId` аккаунта или его прежнего `userId` принимается; файл с неизвестным `userId` — после подтверждения на экране, и этот `userId` становится прежним `userId` аккаунта. Без входа — как раньше.
8. **Синхронизация журнала.** Отправка и получение пачками; курсор — серверный порядковый номер, не время клиента. Идемпотентность по UUID; запись неизменяема — тот же UUID с другим содержимым — ошибка, запись на сервере не меняется. Сервер проверяет схему и размер и **отклоняет записи с временем впереди серверного больше чем на 2 часа**; отклонённые остаются на устройстве и попадают в файл журнала. Офлайн-очередь с повторами; итог — по каждой записи. Записи с неизвестными полями и типами хранятся и передаются целиком. Минимальная версия клиента — сервер отвечает «обновите приложение»; запись с версией правил (`rules`) новее своей — клиент не пересчитывает, а обновляется. FSRS пересчитывается на клиенте из объединённого журнала (детерминизм — тестом двух устройств в разных поясах).
9. **Локальный режим без входа остаётся.** Проверки со сдвигом даты — только без входа, в отдельном профиле Edge.
10. **Настройки.** Синхронизируются: язык интерфейса, язык значений, лимит новых (и будущее целевое удержание, 4.4б). ## Р43. CPU маршрутов входа: тариф, размеры обмена, окно повтора входа

Принято 27.10.2026 (замер `tools/bench/`, план правок А–В подтверждён владельцем с уточнениями). Уточняет Р37 пп. 4–5, Р39 пп. 1, 7, 16. Итог замера и ограничения метода — `docs/STATUS.md`, раздел «Шаг «CPU маршрутов входа»».

1. **Тариф — Free.** Любое Exceeded CPU Time Limits > 0 в 6а.6 или в первые две недели настоящих пользователей — переход на Workers Paid в тот же день (решение владельца). Срок в уведомлении («из резервных копий — не позже 30 дней») верен на обоих тарифах.
2. **Отправка:** пачка устройства — 25 записей (было 100), сервер принимает до 100 (было 200); деление при ошибке — как Р39 п. 16: 25 → 13 → 10.
3. **Получение и выгрузка журнала:** страница — 200 (было 500); больший `limit` сервер урезает, а не отказывает (старые сборки листают по `more`), 0 и не число — 400. При 5xx, сетевой ошибке и 413 устройство делит страницу 200 → 100 → 50, следующая страница — снова 200. Скрипт администратора выгружает страницами по 500 (wrangler, без лимита Worker).
4. **Окно повтора входа — 10 минут** (`RETRY_WINDOW`). Устройство, использовавшее приглашение или код, повторяет вход тем же токеном или кодом и тем же `deviceId`: новая сессия, прежние сессии этого устройства удаляются, больше ничего не пишется, неудачной попыткой не считается. Повтор проходит, только если совпадает с первой попыткой: приглашение account — `localUserId` нет или он равен id аккаунта, и согласие дал тот же (self / parent), что в первый раз; приглашение device и код — `formerUserId` нет, или он равен id аккаунта, или уже прежний номер этого аккаунта; устройство не отключено, аккаунт без пометки удаления. Иначе — 400 invalid, ничего не пишется (выход — новый код с устройства, где вход есть, или ссылка `recover.ts`; «нет» в вопросе о переносе — не выход, а отказ от входа: запрос не отправляется, устройство не входит, прогресс остаётся на нём — `transfer.declinedLink` / `transfer.declinedCode`; уточнено по коду 27.10.2026). Новых столбцов и данных нет: `used_at`, `used_device_id`.
5. **Клиент:** `/api/auth/invite` получает необязательный `deviceId` (иначе повтор по ссылке остановился бы на проверке приглашения); `signInWith` один раз повторяет redeem / pair через ≈ 2 с при сетевой ошибке или 5xx с тем же телом. Новых строк интерфейса нет.
6. **Cron:** использованные приглашения и коды стираются не раньше чем через 10 минут после использования; неиспользованные истёкшие — как прежде. Уведомление сроков хранения приглашений, кодов и сессий не называет (поиск 27.10.2026).
7. **`MIN_CLIENT` не поднимается:** старые сборки шлют не больше 100 записей и листают по `more`; повтор входа работает и для них, кроме повтора по ссылке (без `deviceId`).
8. **Отложено** (резерв, цифры — в STATUS): ускорение хэша записи и `canonicalJson`, слияние обращений к D1 в redeem / pair, кэш ключа HMAC.
