### Чем это отличается от прежнего плана

- **APKG в приложении не поддерживается**; вместо него свой формат колоды (Р2). JSZip остаётся, sql.js не нужен.
- **Три навыка** (`listen`, `speak`, `write`) с отдельным состоянием FSRS и знакомство без оценки (Р3).
- **Правило оценки**: оценку определяет правильность, а не время; время пишется в журнал (Р4). Пороги по времени из этапа 1 в новой версии не используются для оценки.
- **Сверка голоса по звучанию**, орфография только в `write` (Р5). Приравнивание цифр к словам входит сюда.
- **Интерфейс на трёх языках** (таджикский, русский, английский), язык значений отдельно (Р8).
- **Аккаунты, синхронизация и бэкенд** теперь в плане (Р9–Р11); раньше синхронизация была открытым вопросом.
- Прежнее решение «один правильный ответ на карточку» сохранено (Р3).
- **Несколько изучаемых языков** (Р13): язык задаётся колодой, всё языковое — в языковом пакете; сейчас только французский.

## Этап 2: что сделано

Формат дорабатывался дважды по решениям пользователя: Р13 (несколько изучаемых языков), Р14 (`determiner`), Р15 (поля и правила формата; название колоды — имя файла, словарь тегов).

- `docs/DECK_FORMAT.md` — формат `sluh-deck` версии 1: ZIP с `deck.json` и `audio/` (WAV или MP3). Колода: `format`, `version`, `id`, `revision`, `language` (BCP-47), `tags` (словарь: код → названия на tg/ru/en), `entries` (порядок = порядок знакомства). Название колоды — имя ZIP-файла без расширения. Запись: `id`, `text`, `ipa`, `meaning`, `hint`, `note`, `audio`, `gender` (m/f/n), `determiner` (definite/indefinite), `tags` (коды), `skills`. Правила id и обновления колоды (пропавшие записи скрываются, прогресс сохраняется).
- `src/core/sluh-deck.schema.json` — JSON Schema; `src/core/deckFormat.ts` — валидатор (все ошибки сразу, по-русски, с номером и id записи; проверка архива: где `deck.json`, есть ли аудио, регистр букв, лишние файлы, архив больше 20 МБ; предупреждает о тегах без описания). Там же: название колоды из имени файла и выбор текста на языке интерфейса с запасным языком. Тест следит, чтобы схема и валидатор не расходились.
- `src/core/languages.ts` — языковые пакеты (Р13). Пока в пакете: код языка, локаль распознавания и озвучки по умолчанию, название на трёх языках, роды, ряд букв клавиатуры. Нормализация, сверка по звучанию и числа переедут в пакет на этапах 3–4. Есть только французский.
- `scripts/validate-deck.ts` — проверка ZIP на компьютере: `npm run deck:check -- колода.zip` (тот же валидатор и пакеты, что будут в приложении).
- `scripts/convert_apkg.py` — разовый конвертер урока 1 (Python, только стандартная библиотека; не часть приложения). Результат: `decks/Фаронсавӣ · Дарси 01.zip` (папка `decks/` не публикуется).
- `docs/DECK_PROMPT.md` — инструкция для ИИ; существительные — двумя записями (с определённым и неопределённым артиклем); коды тегов `word`, `phrase`, `number`; ИИ предлагает имя ZIP-файла (= название колоды).
- README: оценка по правильности (Р4), а не по скорости. SPEC.md и CLAUDE.md: изучаемый язык — из колоды.
- Новая зависимость: `jszip` (была в утверждённом стеке, нужна скрипту проверки сейчас и импорту на этапе 4).
- Импорт колоды в приложение не делался — это этап 4.

### Конвертация урока 1

- Урок 1 — только образец из Anki: ничего сверх исходника не добавлялось (ни вторых форм существительных, ни `write` у остальных записей).
- `language: fr-FR`, `revision: 1`, файл «Фаронсавӣ · Дарси 01.zip» — это и есть название колоды.
- 30 записей, 30 аудио (WAV, как в исходнике), архив 1,3 МБ; валидатор: без ошибок и предупреждений.
- Français → `text`; IPA → `ipa` (без скобок); Маъно → `meaning.tg`; Аудио → `audio/<id>.wav`.
- Теги из Anki: «вожа» → `word` (15), «адад» → `number` (11), «кор» → `kor` (4, название только на tg: «кор»). Названия `word` и `number` на ru/en («слово»/«word», «число»/«number») дал Claude. Тег урока «U01» не перенесён — вся колода и есть урок 1.
- Навыки: у всех `listen` и `speak`; `write` — у 15 слов, где в Anki было «Навиштан» = y. **Предположение**: `speak` нужен всем записям.
- `determiner` и род — по артиклю: le nom, le prénom, la nationalité, la signature — `definite`; un rendez-vous — `indefinite`. У «monsieur» артикля нет — без рода и формы.
- id записей сделаны из французского текста (`je-m-appelle`, `le-prenom`, `un`…) и дальше не меняются.

## Известные проблемы

- **Разговорные варианты получают «Снова».** Сверка требует точно эталонную фразу: «ça coûte combien» вместо «Combien ça coûte ?» даёт 33 %. Решение принято: каждая формулировка — отдельная запись.
- **«à» и «au» считаются разными словами.** «J'habite au Luxembourg» получает штраф. Это ожидаемо для сверки по словам.
- **Числа.** Распознаватель, скорее всего, вернёт цифры вместо слов («1» вместо «un»); пока это засчитается как ошибка (предположение, не проверено на колоде с числами). Исправление запланировано на этап 4 (сверка по звучанию, Р5).
- **Задержка включения микрофона** иногда достигала 5–12 с (4 раза из 28), после чего пользователь нажимал «Повторить». Причину журнал не показывает, потому что ошибка неудачной попытки не записывается. Пользователь говорит, что не заметил случаев, когда говорил раньше включения. Решение: добавить запись ошибки в журнал, если проблема повторится.
- **Журнал прототипа не перенесён:** у приложения новый адрес.
- Встроенный голос браузера пользователю не нравится. Он остаётся запасным вариантом, пока нет аудио из колоды; отключается в Настройках.
- Журнал хранится в localStorage, последние 300 записей. Резервной копии нет.

## Известные расхождения кода с решениями

Код этапа 1 пока реализует прежние правила; решаем на этапах 3–4:

- Оценка (`src/core/grade.ts`) идёт по порогам времени и точности, а не по правильности (Р4).
- Сверка (`src/core/compare.ts`) идёт по написанию, не по звучанию; цифры не приравниваются к словам (Р5).

- Интерфейс только на русском (Р8).
- Распознавание и сверка в приложении пока жёстко французские (`settings.ts`, `compare.ts`); языковые пакеты (Р13) пока использует только валидатор колоды.
- Журнал в localStorage без UUID и `userId` (Р10).
