### По коду: что происходит и сколько длится [Ф]

1. Ссылка → (Android: «Open with: Chrome / Mana» → **Mana**) → проверка приглашения
   (`POST /api/auth/invite`, ничего не пишет) → уведомление v3 → «Мувофиқам» → «Шумо 16-сола

2. «Бале»: отметка `pendingTransfer` → `POST /api/auth/redeem` с `localUserId` → аккаунт получает
   номер установки телефона; записи телефона **не переписываются** (Р40 п. 1); одна транзакция
   Dexie ставит все записи в очередь и отметку «сначала получение».
3. Обмен: получение с курсора 0 (у нового аккаунта пусто — 1 запрос) → отправка пачками по 25 с
   паузой 2 с; первая пачка — с настройками в режиме `init`. Для N = 510 — 21 пачка: ≈ 40 с пауз
   + 21 запрос — **около минуты** [Р].
4. Если свернуть приложение посреди отправки — уходит одна пачка `keepalive` (до 25 записей,
   ≤ 60 КиБ, только записи); остальное — при следующем открытии. Если пропадёт сеть — обмен
   останавливается, очередь остаётся и уходит при появлении сети или при запуске. Повтор
   безопасен: записи, уже дошедшие до сервера, получают `duplicate` [Ф]. Потерь нет; но для
   замера **не сворачивать** до очереди 0.
5. При неудачном входе — один автоповтор через 2 с; затем «Хатое рух дод. Баъдтар дубора талош
   кунед.» → **повторить сразу, в течение 10 минут** (окно повтора, Р43 п. 4; STATUS, открытый

## Е. Фоновая отправка (keepalive) в установленном приложении

По коду [Ф]: при уходе страницы в фон (`visibilitychange` → hidden) уходит одна пачка очереди —
до 25 записей и ≤ 60 КиБ, **только записи** (без настроек), запрос `fetch` с `keepalive`, без
ожидания ответа. Обычная отправка — только через 8 с после ответа, поэтому свёрнутое раньше 8 с
приложение отправляет ответ именно так. Ответ сервера может не дойти до страницы — тогда запись
при следующем открытии уйдёт ещё раз и получит `duplicate`. Как увидеть: запись есть на ноутбуке
и на сервере, а телефон после ответа не открывали.
